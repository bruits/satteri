# Attributes

`Options::ENABLE_ATTRIBUTES` reads curly-brace attributes (`{#id .class key=value}`)
on more elements than headings, with the same syntax and merge rules as heading
attributes. It also enables heading attributes:

```````````````````````````````` example
# Heading {.title #top}
.
<h1 class="title" id="top">Heading</h1>
````````````````````````````````

## Fenced code

A fenced code block's info string can end with an attribute block. The
attributes go on the `<code>`, as in markdown-it-attrs:

```````````````````````````````` example
```js {#snippet data-lang=javascript}
x
```
.
<pre><code class="language-js" id="snippet" data-lang="javascript">x
</code></pre>
````````````````````````````````

The language is written before the braces, so its class comes first, holding
any attribute classes followed by the language class:

```````````````````````````````` example
```js {.highlight}
x
```

```ts {.foo #bar data-lang=typescript}
x
```
.
<pre><code class="highlight language-js">x
</code></pre>
<pre><code class="foo language-ts" id="bar" data-lang="typescript">x
</code></pre>
````````````````````````````````

Without a language, the attributes keep the order they are written in:

```````````````````````````````` example
``` {#plain .text}
x
```
.
<pre><code id="plain" class="text">x
</code></pre>
````````````````````````````````

The block needs no space before it, and tilde fences take attributes too:

```````````````````````````````` example
```js{.a}
x
```

~~~js {.a}
x
~~~
.
<pre><code class="a language-js">x
</code></pre>
<pre><code class="a language-js">x
</code></pre>
````````````````````````````````

Text before the block stays in the info string's meta, and only the last of
several blocks is read:

```````````````````````````````` example
```js title="x" {.a}
x
```

```js {.a} {.b}
x
```
.
<pre><code class="a language-js">x
</code></pre>
<pre><code class="b language-js">x
</code></pre>
````````````````````````````````

A block that doesn't end the info string, an empty block, and an unclosed one
are not attributes:

```````````````````````````````` example
```js {.a} extra
x
```

```js {}
x
```

```js {.a
x
```
.
<pre><code class="language-js">x
</code></pre>
<pre><code class="language-js">x
</code></pre>
<pre><code class="language-js">x
</code></pre>
````````````````````````````````

## Inline elements

A block written right after an inline element, with no space between, goes on
that element: emphasis, strong, code spans, links, images and strikethrough:

```````````````````````````````` example
*em*{.a} **strong**{#b} `code`{c=d}
.
<p><em class="a">em</em> <strong id="b">strong</strong> <code c="d">code</code></p>
````````````````````````````````

```````````````````````````````` example
[link](/u){.a} ![alt](/i.png){.b} [ref][r]{#c}

[r]: /r
.
<p><a href="/u" class="a">link</a> <img src="/i.png" alt="alt" class="b"> <a href="/r" id="c">ref</a></p>
````````````````````````````````

```````````````````````````````` example
~~gone~~{.x}
.
<p><del class="x">gone</del></p>
````````````````````````````````

Nested elements each take their own block, and blocks that follow one another
merge:

```````````````````````````````` example
**a *b*{.in}**{.out}

*em*{.a}{#i}{.b k=v}
.
<p><strong class="out">a <em class="in">b</em></strong></p>
<p><em class="a b" id="i" k="v">em</em></p>
````````````````````````````````

Characters that are markup elsewhere are plain text inside a block:

```````````````````````````````` example
*em*{.a_b}
.
<p><em class="a_b">em</em></p>
````````````````````````````````

A block after a space or after plain text, an escaped brace, and an empty or
unclosed block stay text:

```````````````````````````````` example
*em* {.a} text{.b} *em*\{.c} *em*{} *em*{.d
.
<p><em>em</em> {.a} text{.b} <em>em</em>{.c} <em>em</em>{} <em>em</em>{.d</p>
````````````````````````````````
